# Azeroth Voices V0.8 — Party/Raid Chatter, Guild Depth, Memory Ledger

## Summary

Port the reference module's group, guild and memory behaviour into the existing in-process architecture (worker pool, priority queues, cooldowns, world-thread delivery, fail-soft SQL, `.av` controls). Nothing leaves the module: no Python bridge, no core or PlayerBots edits, no new provider shapes. Work is staged so each stage is independently shippable and testable.

Locked decisions: real players must be present (bot-only groups stay silent); conservative defaults with every trigger shipping enabled and individually tunable; deterministic C++ memory summaries only (no extra provider calls, no player-written text stored); simple one-line guild login greeting; memories persisted in a new character-DB table with RAM fallback; party chatter anywhere the group is, raid-flavoured chatter only on raid maps.

## Implementation Changes

**Stage 1 — Party and raid chatter** (new `AzerothVoicesGroupChatter.*`, extending the existing script/manager pipeline)

- New triggers, all Say/Yell-free and delivered to Party (or Raid) only after the existing real-audience check re-runs before delivery: idle, dungeon entry, zone transition, trash kill, boss pull, boss kill, wipe, player death, corpse run (`ON_PLAYER_RELEASED_GHOST`), resurrect observed, loot by rarity, quest accept/objective/complete, spell cast (`ON_SPELL_CAST`), low health, low mana, nearby object, bot question, and a bounded second-bot follow-up after a real player's group message.
- New hooks used: `ON_PLAYER_RELEASED_GHOST`, `ON_SPELL_CAST`, `ON_UPDATE_ZONE`, `ON_MAP_CHANGED`, `ON_LOGOUT`. Everything without a hook (idle, low health/mana, wipe, nearby object, bot question, quest accept/objective progress) runs on a bounded per-group scan in the existing world tick — quest accept/objective by diffing each grouped bot's quest-log counters, not by packet sniffing (PlayerBots do not emit those packets).
- Boss moments reuse the existing curated boss registry: pull = first combat with a classified boss while the group is engaged; kill = `ON_CREATURE_KILL` on a classified boss; wipe = all group members dead and out of combat. These are a different trigger family from the existing pre-aggro boss dialogue and never change threat, aggro, facing or movement.
- Multi-line conversations reuse the proximity conversation model (new bounded group-conversation map, max 3 lines, 6-second turn gap, 30-second reply window, max 2 participants, 3 reply turns) with one provider request per turn; automated group lines are not paced by the World/custom-channel timeline.
- Raid maps additionally enable battle cry on pull, morale, and raid idle; boss pull/kill/wipe fire in dungeons too, delivered to Party there and Raid in raids.
- Conservative defaults (per trigger chance %, cooldown s): idle 5/120, dungeon entry 60/300, zone 15/180, trash kill 8/180, boss pull 50/300, boss kill 80/300, wipe 80/300, death 25/60, corpse run 40/300, resurrect 50/120, loot 10/35/70/100 by green/blue/purple/orange with 120, quest accept 25, objective 20, complete 25 at 60 with a 60 debounce, spell cast 8/60, low health 40 at 35 % HP, low mana 30 at 20 % mana, both 180, nearby object 10/300 on a 60 scan, bot question 1/300 on a 60 scan, player-message follow-up 15/30; raid extras: battle cry 40/300, morale 15/300 on a 120 scan, raid idle 10/180 on a 60 scan.
- New switches: `AzerothVoices.GroupChatter.*` and `AzerothVoices.RaidChatter.*`; group lines still require `Replies.Party`/`Replies.Raid`, obey actor cooldowns, the global rate limit, `.av pause`, and the new chatty-preset coverage, but are exempt from `DisableRepliesInCombat` because in-combat callouts are the feature's purpose.

**Stage 2 — Guild depth** (`AzerothVoices.GuildChatter.*`)

- Ambient guild conversations on a bounded scan (60 s, chance 8, guild cooldown 600 s) with conversation chance 35, max 2 participants and 3 lines, plus cheap prompt decorations: participant reference 20, zone name 15, recent-history context 25 (reusing the existing history store), all bounded and charged to the context budget.
- Player-reply gating on top of the existing guild reply path: 5-second debounce per speaker and suppression of the bot that spoke most recently in the last 30 s; multi-addressed bonus is not ported (the existing responder falloff already covers multiple responders).
- Simple login greeting: when a real guild member logs in and at least one guilded bot is online, one bounded one-line greeting at 50 % with a per-recipient 30-minute cooldown, using the existing `guild_login` path. No readiness timeout, retry loop or multi-reply.
- No guild session-summary provider calls; continuity comes from conversation history plus the Stage 3 memories.

**Stage 3 — Deterministic memory ledger** (`AzerothVoicesMemory.*`, new migration `data/sql/character/20260912_02_azeroth_voices_memories.sql`)

- New table `azeroth_voices_bot_memory` in the character DB: `id`, `bot_guid`, `player_guid`, `memory_type`, `summary`, `importance`, `created_at`, `updated_at`, primary key on `id`, index on `(bot_guid, player_guid, created_at)`, index on `updated_at`. Additive only; no existing table or column changes; missing table degrades to bounded RAM exactly like personality and sentiment.
- C++ writes fixed-template summaries (≤180 characters) from verified facts only: `first_met`, `party_member`, `quest_completed`, `dungeon_completed`, `level_up`, `boss_kill`, `pvp_kill`, `wipe`, `achievement`. Deterministic generation chances 20/25/25/30/40/50/20/50/30. No player-written text is ever stored and no provider call is made.
- Bounded lazy RAM cache (4096 pairs) and coalesced dirty writes; hourly cleanup keeps the newest 30 rows per pair and deletes rows untouched for 180 days.
- Retrieval injects a bounded "THINGS YOU REMEMBER ABOUT `<player>`" block (max 3 items, 600 characters) ranked by importance then recency, charged against the context budget below personality; recall is prompt-only, with a 15 % chance that an ambient/group line references one memory.
- The Chatter addon's `forget` now also deletes that player/bot pair's memories (matching the addon's own promise); `.av clearhistory` still does not touch memories. New `.av memory inspect <bot> <player>` and `.av memory forget <bot> <player>|all` report and delete explicitly.

## Interfaces, Data, and Defaults

- New conf groups, inserted next to the NPC/proximity/boss sections and renumbered in the file index: `AzerothVoices.GroupChatter.*`, `AzerothVoices.RaidChatter.*` (Stage 1), `AzerothVoices.GuildChatter.*` (Stage 2), `AzerothVoices.Memory.*` (Stage 3). Every key is consumed by the loader; no dead keys ship.
- New pure-kernel headers so the decisions are unit-testable without the world: group trigger gating, wipe detection, quest-log diff, group conversation budget, loot-rarity mapping, memory summary formatting/ranking/pruning, greeting gating.
- Existing `.av` commands, provider, history, RAG, personality, sentiment, proximity, boss dialogue, pacing and addon protocol keep current behaviour; the quieter preset gains entries for the new systems.
- Public seam unchanged: `Manager::HandleEvent` remains the adapter entry point (achievement and dungeon-completed memories use it).

## Test Plan

- Unit tests extending the existing standalone suite: conservative default table and clamps; trigger gating precedence (audience, cooldown, in-combat exemption, raid-map restriction); wipe detector across partial deaths, resurrects and combat exit; quest-log diff for accept vs objective vs completion; group conversation budget (3 lines, 6-second gap, 30-second window, 2 participants); loot rarity to chance mapping; memory summary templates, ranking, 30-row and 180-day pruning, and forget scoping; greeting gating (real member, online guilded bot, per-recipient cooldown, one responder).
- Build checks: static Release `mangosd` with PlayerBots and Turtle addons still links; `ctest -C Release` green.
- Live checks (documented as required, not claimed): real player grouped with bots in the open world and in a dungeon/raid; wipe, corpse run and boss pull/kill lines; no bot-only chatter; party/raid lines respect the subgroup and raid audience; guild conversation and login greeting across two accounts; memory rows written, retrieved in later prompts, deleted by addon Forget and by `.av memory forget`; RAM fallback with the migration uninstalled.

## Assumptions

- Out of scope and left unported: battleground chatter, emote reactions, weather/holiday/transport/zone-intrusion/race-lore/day-night flavour systems, native Anthropic/Google/Ollama adapters, the request log and health probe, and everything requiring the Python bridge or a client-side screenshot agent.
- Group and raid chatter never speak for classified bosses outside the existing boss subsystem, and never alter threat, aggro, facing or movement.
- Memory rows are per bot/player pair and are not shared between players; forgetting is always explicit and scoped.
- PlayerBots are required, as the module already assumes; nothing here enables or requires Bot-only group chatter.
