# v0.7 — Lightweight OpenAI + Gemini Thinking

## Summary

- Implement in `C:\Users\Admin\Downloads\mod-azeroth-voices\mod-azeroth-voices`, retaining all current main/dev-derived local features and unrelated edits.
- Add official OpenAI and official Gemini OpenAI-compatible Thinking support only; retire the existing generic `AzerothVoices.ReasoningEffort` path so proxies and other compatible providers remain normal non-thinking providers.
- Add a small `AzerothVoicesReasoning.{h,cpp}` helper for policy, detection, AutoKinds, safe JSON changes, and reasoning-rejection fallback.

## Key changes

- Add and document exactly:
  - `AzerothVoices.Thinking.Mode = Auto`
  - `AzerothVoices.Thinking.AutoDetect = 1`
  - `AzerothVoices.Thinking.Effort = Low`
  - `AzerothVoices.Thinking.TokenReserve = 1024`
  - `AzerothVoices.Thinking.AutoKinds = PersonalityGeneration,EventChat`
- Parse six case-insensitive, whitespace-trimmed AutoKinds with duplicate suppression and non-fatal invalid-value warnings:
  `PersonalityGeneration`, `DirectChat`, `TargetedNpc`, `EventChat`, `AmbientChat`, `FollowupChat`.
- Classify purpose independently of channel:
  - Personality request kind → `PersonalityGeneration`
  - `direct-chat` → `DirectChat`
  - Normalize current selected/named/scene NPC request triggers to `targeted-npc-*` → `TargetedNpc`
  - `event:*` → `EventChat`
  - `ambient` → `AmbientChat`
  - `generated-followup` → `FollowupChat`
  - `overheard-chat`, GM tests, boss/proximity triggers, and unknown future triggers remain non-reasoning in Auto mode.
- Detect only official HTTPS endpoint shapes:
  - `api.openai.com/v1/chat/completions` and `/v1/responses`
  - `generativelanguage.googleapis.com/v1beta/openai/chat/completions`
  - All other endpoints receive no Thinking fields.
- Use conservative no-probe model capability recognition:
  - `gpt-4.1*` is unsupported/non-reasoning.
  - Current supported GPT reasoning and o-series families are classified from official OpenAI documentation.
  - Gemini 2.5 controllable models are `Optional`; Gemini 2.5 Pro and Gemini 3.x are `AlwaysOn`.
  - Unknown models are `Unknown` and receive no optional controls.
- Preserve OpenAI request modes:
  - Responses: `reasoning: { "effort": "low|medium|high" }`
  - Chat Completions: supported official OpenAI reasoning control only
  - Gemini OpenAI compatibility: `reasoning_effort`, never `thinking_level`, `thinking_budget`, native SDK fields, or thought summaries.
- Apply policy:
  - `Auto`: supported provider/model plus enabled AutoKind.
  - `On`: supported provider/model regardless of AutoKinds.
  - `Off`: omit optional control; use the lowest documented control for `AlwaysOn` models without claiming reasoning is disabled.
- Add `TokenReserve` only when a reasoning control is applied, using the active provider output-token field while retaining existing visible reply splitting.
- Parse custom `AiPlayerbot.LLMApiJson` as JSON; preserve an explicit user reasoning setting and inject no duplicate/conflicting field.
- Keep only minimal local metadata for request processing. Never place raw reasoning in chat, logs, histories, RAG, snapshots, personality, sentiment, or SQL.
- On a parameter-specific official-provider rejection, atomically mark the current capability unsupported and retry the same request once without optional reasoning; count it through existing retry telemetry and prevent loops.
- Extend status/debug output with mode, provider, capability, effort, and enabled AutoKinds; do not add a separate debug option.
