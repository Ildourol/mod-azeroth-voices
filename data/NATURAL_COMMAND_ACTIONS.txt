AZEROTH VOICES NATURAL-COMMAND ACTION CATALOG
================================================

Source verified against this checkout:
src/modules/PlayerBots/playerbot/strategy/triggers/ChatTriggerContext.h

Use these exact names or the presets below in AzerothVoices.NaturalCommands.AllowedActions,
separated by commas. Presets and exact names may be mixed; the resolved set removes duplicates.
The allowlist controls only commands interpreted by Azeroth Voices; native PlayerBots command
syntax is still handled and secured by PlayerBots.

OPTIONAL PRESETS
----------------
light (20): accept, attack, buff, equip, flee, follow, free, guard, loot, position, pull, quests,
ready, release, revive, stats, stay, talk, use, who

medium (72): every non-forbidden action in usefulness sections 1 and 2 below. This is the balanced
default for new configurations. It includes light automatically, plus the remaining essential,
questing, inventory, travel, character, and information actions in those two sections.

heavy (131): every non-forbidden action in sections 1 through 4. `*` is an alias for heavy.

Examples:
  AzerothVoices.NaturalCommands.AllowedActions = light
  AzerothVoices.NaturalCommands.AllowedActions = medium,emote,craft
  AzerothVoices.NaturalCommands.AllowedActions = light,cast,equip

The last example resolves to 21 unique actions: equip is already in light, so it is not duplicated.

ShortlistMaximum is capped by the resolved allowlist after preset expansion. Set it to 0 to send
every resolved allowed action, or use 1-131 as a positive cap. A fitting allowlist is included
completely; a larger allowlist may be reduced below its cap by relevance scoring for an obvious
instruction.

The interpreter defaults to one PlayerBot and one action per message. Configuration can permit up
to five explicitly named recipients and three independent actions; it never performs implicit
fan-out or stateful multi-step workflows. Valid WoW links are replaced by bounded local placeholders
for classification and restored byte-for-byte before the existing PlayerBots parser receives the
command. An allowed action does not guarantee success: PlayerBots still checks ownership/security,
target, inventory, spell, state, range and the command's own requirements. "Dispatched" means only
that Azeroth Voices called PlayerBots' void command API.

For reliable separation, set `AiPlayerbot.CommandPrefix = !` in PlayerBots' aiplayerbot.conf.
Azeroth Voices reads that value but does not own or edit it. If the native prefix is empty, native
PlayerBots may process the chat first and the module refuses to claim or perform a second dispatch.

RISK AND CONFIRMATION
---------------------
Low-risk actions are dispatched after local/provider validation. Caution actions receive the same
strict validation and private feedback. High-risk interpreted actions require the same real player
to address the same PlayerBot with `confirm` before the bounded confirmation TTL; `cancel` discards
the pending action. Native prefixed commands remain governed by PlayerBots, not this confirmation.

High risk includes auction bids/purchases, vendor buys, quest drops, trades/sales/mail, group or
guild leadership/membership changes, guild member management, AI load/save/reset, skill/talent
changes, and major travel/teleport commands. The six actions in the permanent-forbidden section can
never be enabled for interpretation. The remaining advanced/specialized actions are caution risk;
ordinary movement, combat, reporting, and non-destructive quest/item actions are normally low risk.

PERMANENTLY FORBIDDEN TO THE NATURAL-LANGUAGE INTERPRETER (6)
-------------------------------------------------------------
cdebug - Privileged PlayerBots debug command.

debug - Privileged PlayerBots debug command.

set value - Set an internal AI value.

These six remain native PlayerBots inputs, but Azeroth Voices rejects them even if *, heavy, or
their exact names are placed in AllowedActions. This prevents a model-produced command from mutating
privileged, destructive or unbounded internal state. No PlayerBots core behavior was changed.

RECIPIENT RULES
---------------
Whisper: the whispered PlayerBot.
Say: one selected PlayerBot, or explicitly named PlayerBots within SayDistance.
Yell: explicitly named PlayerBots within YellDistance.
Party: explicitly named PlayerBots in the same party subgroup, or the subgroup's single eligible
PlayerBot without a name. Multiple eligible subgroup bots require explicit naming.
Raid: explicitly named PlayerBots in the same raid.
Guild: explicitly named PlayerBots in the same guild.
Officer: explicitly named PlayerBots in the same guild with officer-chat listen rights.
World: exact explicitly named online PlayerBots.
Custom channel: exact explicitly named online PlayerBots.

MasterOnly=1 additionally requires that the speaking real player is the bot's current master.
NPCs are never candidates. Named recipients are capped by MaximumRecipients (default 1); no nearby,
group, guild, World, or custom-channel audience is implicitly converted into command recipients.

Azeroth Voices GM Command Reference
===================================

Primary command prefix: .av
Required security: vMaNGOS moderator/GM, or the server console where supported.

Status and diagnostics
----------------------
.av
    Show the same concise runtime summary as .av status.

.av status
    Show module, worker, queue, storage, personality, RAG, model, and endpoint status.

.av test
    Run the private read-only global test. No provider request or database mutation occurs.

Runtime control
---------------
.av pause
    Stop accepting new Azeroth Voices work while already queued delivery may finish.

.av resume
    Resume accepting Azeroth Voices work.

.av restart
    Restart the manager and workers using configuration already loaded by the core.
    This command does not reread edited configuration files from disk.

.av clearhistory
    Clear Azeroth Voices conversation, surrounding-chat, and snapshot history.
    Personality records are not deleted.

Generation tests
----------------
.av chatter [optional topic]
    Queue one ambient chatter attempt. Requires an in-game GM.

.av live <exact-online-bot-name> [optional prompt]
    Queue one provider-backed line from the selected online PlayerBot. Requires an in-game GM.

.av live - [optional prompt]
    Queue one provider-backed line from an automatically selected nearby actor. Requires an in-game GM.

Persistent PlayerBot personalities
----------------------------------
.av personality show <exact-online-bot-name>
    Display the currently cached or stored personality.

.av personality status <exact-online-bot-name>
    Display the bounded last generation state and sanitized failure information for this session.

.av personality regenerate <exact-online-bot-name>
    Queue a replacement personality. A usable existing personality remains active until replacement succeeds.

.av personality delete <exact-online-bot-name>
    Delete only that bot's Azeroth Voices personality cache, pending generation, and persistent row.

.av personality delete all
    Delete all Azeroth Voices personality records and pending personality jobs.
    Conversation history, snapshots, Environment, RAG, character data, and PlayerBots data are not deleted.
